# Спецификация: «Утка Разраба»

> **Версия:** 1.1  
> **Роль автора:** Старший бизнес-аналитик  
> **Целевая платформа:** Android (RuStore)  
> **Концепция:** Rubber Duck Debugging — приложение с интерактивной уткой, которой разработчик может объяснять свои проблемы, получая звуковую/визуальную обратную связь.

---

## 1. User Stories

### US-01: Тап по утке для получения кряка

**Как** разработчик, **я хочу** нажимать на утку и слышать кряк, **чтобы** получить мгновенную звуковую обратную связь в стиле rubber duck debugging.

**Acceptance Criteria:**
- Given приложение запущено, When пользователь нажимает на область утки, Then воспроизводится звук кряка.
- Given звук уже воспроизводится, When пользователь нажимает повторно, Then предыдущий звук корректно прерывается и начинается новый (debounce ≤ 300 ms).
- Given устройство в режиме «без звука», When пользователь нажимает на утку, Then кряк не воспроизводится (или вибрирует — зависит от настроек).

---

### US-02: Выбор типа кряка

**Как** разработчик, **я хочу** выбирать тип кряка из списка доступных звуков, **чтобы** разнообразить взаимодействие и подстроить его под настроение.

**Acceptance Criteria:**
- Given пользователь открыл экран настроек, When он выбирает конкретный кряк из списка, Then при каждом нажатии на утку воспроизводится именно этот кряк.
- Given выбран конкретный кряк, When пользователь нажимает на утку, Then воспроизводится выбранный звук.
- Given пользователь выбирает режим «Случайный кряк», When нажимает на утку, Then воспроизводится один из доступных звуков в случайном порядке.
- Список кряков содержит минимум 5 вариантов (предустановленных).
- Предустановленные кряки берутся из библиотек звуков (пресеты), короткие (≤1 sec), монофоничные.
- Формат звуковых файлов — WAV (PCM 16-bit mono) как самый простой без сжатия.
- Каждый кряк доступен для предпрослушивания в настройках.

---

### US-03: Настройка кряка по умолчанию

**Как** разработчик, **я хочу** установить один конкретный кряк как кряк по умолчанию, **чтобы** при каждом запуске приложения он уже был активен без ручной настройки.

**Acceptance Criteria:**
- Given пользователь выбрал кряк и пометил его как «по умолчанию», When приложение перезапускается, Then активен именно этот кряк.
- Given выбран режим «Случайный кряк» как по умолчанию, When приложение запускается, Then при первом нажатии на утку воспроизводится случайный звук.

---

### US-04: Изменение цвета утки

**Как** разработчик, **я хочу** менять цвет утки, **чтобы** визуально кастомизировать приложение под своё настроение или эстетику рабочего стола.

**Acceptance Criteria:**
- Given пользователь открыл палитру цветов, When он выбирает цвет, Then утка мгновенно перекрашивается в выбранный цвет.
- Given цвет изменён, When приложение перезапускается, Then цвет утки сохраняется (persistent storage).
- Доступно минимум 8 предустановленных цветов + возможность выбора произвольного цвета через color picker.
- Цвет утки сохраняется между сессиями.
- По умолчанию цвет утки желтый.

---

### US-05: Виджет на рабочем столе

**Как** разработчик, **я хочу** добавить виджет с уткой на рабочий стол, **чтобы** взаимодействовать с уткой без открытия приложения — прямо из IDE.

**Acceptance Criteria:**
- Given виджет добавлен на рабочий стол, When пользователь нажимает на утку в виджете, Then воспроизводится кряк (активный кряк из настроек приложения).
- Given виджет добавлен на рабочий стол, When пользователь нажимает на утку, Then утка на виджете проигрывает анимацию (покачивание/моргание/вибрация).
- Given пользователь длительно нажимает (long press) на виджет, When появляется контекстное меню, Then доступна опция «Открыть приложение».
- Виджет поддерживает 3 размера: 2×2, 4×2, 4×3 ячеек.
- Виджет отображает текущий цвет утки из настроек приложения.
- Виджет автоматически обновляется при изменении настроек (цвет, активный кряк) в основном приложении.

---

### US-06: Сохранение состояния при закрытии

**Как** разработчик, **я хочу**, чтобы приложение запоминало мои настройки (кряк, цвет), **чтобы** каждый раз не настраивать заново.

**Acceptance Criteria:**
- Given пользователь изменил настройки, When закрыл и снова открыл приложение, Then настройки сохранены.
- Given приложение было принудительно закрыто ОС, When открыто вновь, Then настройки сохранены.
- Данные хранятся локально (SharedPreferences / DataStore). Облачная синхронизация не предполагается (V1).

---

### US-07: Анимация утки при кряке

**Как** разработчик, **я хочу**, чтобы утка визуально реагировала на нажатие (анимация), **чтобы** взаимодействие ощущалось живым и занимательным.

**Acceptance Criteria:**
- Given утка на экране, When пользователь нажимает на неё, Then воспроизводится анимация (покачивание, вздрагивание или подпрыгивание) синхронно со звуком.
- Given анимация уже проигрывается, When пользователь нажимает повторно, Then анимация сбрасывается и начинается заново.
- Виджетная утка также проигрывает упрощённую анимацию при нажатии.

---

### US-08: Экран приветствия / онбординг

**Как** новый пользователь, **я хочу** увидеть короткий экран-подсказку при первом запуске, **чтобы** понять, зачем эта утка и как с ней взаимодействовать.

**Acceptance Criteria:**
- Given приложение запущено впервые, When пользователь видит главный экран, Then отображается одностраничный онбординг с текстом «Объясни утке свою проблему. Нажми на неё!».
- Given пользователь нажал «Понятно» (или свайпнул), When онбординг закрыт, Then он больше не показывается при следующих запусках.
- Онбординг показывается ТОЛЬКО при первом запуске; при обновлениях приложения не повторяется.

---

### US-09: Запись своего звука кряка

**Как** разработчик, **я хочу** записать собственный звук кряка через микрофон (до 5 секунд), **чтобы** у утки был мой персональный голос и кряк был уникальным.

**Acceptance Criteria:**
- Given пользователь открыл экран настроек, When он нажимает «Записать свой кряк», Then открывается экран записи с таймером до 5 секунд.
- Given запись идёт, When превышен лимит 5 секунд, Then запись автоматически останавливается.
- Given запись завершена, When пользователь прослушивает предпросмотр, Then он может сохранить или перезаписать.
- Given запись сохранена, When пользователь нажимает на утку, Then воспроизводится записанный звук.
- Запись сохраняется локально в persistent storage.
- Записанного кряка можно удалить и вернуться к предустановленным.

---

### US-10: Поддержка TalkBack (доступность)

**Как** незрячий или слабовидящий пользователь, **я хочу** иметь озвученные элементы интерфейса (TalkBack), **чтобы** пользоваться приложением наравне с остальными.

**Acceptance Criteria:**
- Given включён TalkBack, When пользователь наводит фокус на утку, Then озвучивается «Утка. Нажмите, чтобы услышать кряк».
- Given включён TalkBack, When пользователь выбирает кряк в настройках, Then название кряка озвучивается.
- Given включён TalkBack, When пользователь нажимает «Записать кряк», Then озвучивается «Начать запись».
- Все кнопки и интерактивные элементы имеют contentDescription.

## 2. Use Cases

### UC-01: Крякнуть на утку

| Поле | Значение |
|---|---|
| **Название** | Крякнуть на утку |
| **Акторы** | Разработчик (primary) |
| **Pre-conditions** | Приложение установлено и запущено. Основной экран с уткой отображается. Звуковые файлы загружены. |
| **Post-conditions** | Воспроизведён звук кряка. Анимация утки выполнена. Состояние приложения не изменено (настройки не затронуты). |

**Основной сценарий:**
1. Пользователь видит утку на главном экране.
2. Пользователь нажимает на область утки.
3. Система воспроизводит активный звук кряка.
4. Система запускает анимацию утки.
5. Звук и анимация завершаются.

**Альтернативные сценарии:**
- **5a.** Если устройство в режиме «Без звука» (silent mode): система воспроизводит только анимацию без звука. Если в настройках включена вибрация — выполняется вибрация.
- **5b.** Если выбран режим «Случайный кряк»: система выбирает случайный звук из доступного пула перед воспроизведением.
- **5c.** Если пользователь нажимает повторно во время воспроизведения: текущий звук прерывается, запускается новый.

**Обработка ошибок:**
- Если звуковой файл повреждён или недоступен: система воспроизводит звук по умолчанию (fallback) и логирует ошибку.

---

### UC-02: Выбрать тип кряка

| Поле | Значение |
|---|---|
| **Название** | Выбрать тип кряка |
| **Акторы** | Разработчик (primary) |
| **Pre-conditions** | Приложение установлено и запущено. Экран настроек доступен. Доступен минимум 1 звуковой файл кряка. |
| **Post-conditions** | Активный кряк изменён. Настройка сохранена в persistent storage. |

**Основной сценарий:**
1. Пользователь открывает экран настроек.
2. Пользователь переходит в секцию «Выбор кряка».
3. Система отображает список доступных кряков с названиями и кнопками предпрослушивания.
4. Пользователь нажимает кнопку предпрослушивания рядом с нужным кряком.
5. Система воспроизводит звук для предпрослушивания.
6. Пользователь выбирает нужный кряк (нажатие / toggle).
7. Система сохраняет выбор.
8. При следующем нажатии на утку воспроизводится выбранный кряк.

**Альтернативные сценарии:**
- **4a.** Пользователь выбирает «Случайный кряк»: при каждом нажатии на утку системой выбирается случайный звук из пула.
- **4b.** Пользователь устанавливает кряк как «по умолчанию»: при следующем запуске приложения этот кряк будет активен автоматически.

**Обработка ошибок:**
- Если ни один звуковой файл не загружен: показать сообщение «Нет доступных звуков. Переустановите приложение.» и деактивировать выбор.

---

### UC-03: Изменить цвет утки

| Поле | Значение |
|---|---|
| **Название** | Изменить цвет утки |
| **Акторы** | Разработчик (primary) |
| **Pre-conditions** | Приложение установлено и запущено. Экран настроек доступен. |
| **Post-conditions** | Цвет утки изменён. Настройка сохранена в persistent storage. Изменение отражено на главном экране и виджете. |

**Основной сценарий:**
1. Пользователь открывает экран настроек.
2. Пользователь переходит в секцию «Цвет утки».
3. Система отображает набор предустановленных цветов (минимум 8) и кнопку «Свой цвет».
4. Пользователь выбирает предустановленный цвет.
5. Система применяет цвет к утке на предпросмотре.
6. Пользователь подтверждает выбор.
7. Система сохраняет цвет в persistent storage.
8. Утка на главном экране и виджете обновляется.

**Альтернативные сценарии:**
- **4a.** Пользователь нажимает «Свой цвет»: открывается color picker. Пользователь выбирает произвольный цвет через wheel/slider. Система применяет и сохраняет.

**Обработка ошибок:**
- Если color picker недоступен (ошибка рендеринга): показать предустановленные цвета как единственный вариант.

### UC-04: Добавить/настроить виджет

| Поле | Значение |
|---|---|
| **Название** | Добавить и использовать виджет |
| **Акторы** | Разработчик (primary), ОС Android (secondary) |
| **Pre-conditions** | Приложение установлено. На главном экране рабочего стола есть место для виджета. Приложение предоставляет AppWidgetProvider. |
| **Post-conditions** | Виджет отображается на рабочем столе. Нажатие на виджет воспроизводит кряк. Настройки синхронизированы с основным приложением. |

**Основной сценарий:**
1. Пользователь длительно нажимает на пустую область рабочего стола.
2. Пользователь выбирает «Виджеты» из меню.
3. Пользователь находит виджет «Утка Разраба» в списке.
4. Пользователь выбирает один из трёх размеров (2×2, 4×2, 4×3).
5. Пользователь перетаскивает виджет на рабочий стол.
6. Виджет подстраивается под доступное место (resize options).
7. Система отображает утку на виджете с текущим цветом из настроек.
8. Пользователь нажимает на утку в виджете.
9. Система воспроизводит активный кряк и анимацию.

**Альтернативные сценарии:**
- **8a.** Long press на виджете: показывается контекстное меню с опцией «Открыть приложение». Выбор опции — открывается основной экран приложения.
- **8b.** Виджет обновляется при изменении цвета утки или активного кряка в приложении (onUpdate callback).
- **8c.** Пользователь меняет размер виджета перетаскиванием после размещения: виджет перерисовывается под новый размер без потери настроек.

**Обработка ошибок:**
- Если приложение удалено, но виджет остался: виджет отображает заглушку «Приложение удалено» и деактивируется.
- Если AppWidgetProvider не отвечает: виджет перерисовывается при следующем обновлении (AppWidgetManager.updateAppWidget).

### UC-05: Пройти онбординг

| Поле | Значение |
|---|---|
| **Название** | Первый запуск и онбординг |
| **Акторы** | Разработчик (primary) |
| **Pre-conditions** | Приложение запущено впервые (флаг first_launch = true в SharedPreferences). |
| **Post-conditions** | Пользователь видит главный экран с уткой. Флаг first_launch установлен в false. |

**Основной сценарий:**
1. Система определяет, что это первый запуск.
2. Система отображает онбординг-экран: короткий текст + иллюстрация утки + кнопка «Понятно».
3. Пользователь читает текст и нажимает «Понятно».
4. Система закрывает онбординг, устанавливает first_launch = false.
5. Отображается главный экран с уткой.

**Альтернативные сценарии:**
- **3a.** Пользователь свайпает влево: онбординг закрывается (если он многостраничный, показывается следующий экран).

**Обработка ошибок:**
- Если SharedPreferences недоступны: считать первый запуск и показать онбординг.

---

### UC-06: Записать свой звук кряка

| Поле | Значение |
|---|---|
| **Название** | Записать свой звук кряка |
| **Акторы** | Разработчик (primary) |
| **Pre-conditions** | Приложение установлено и запущено. Микрофон доступен. Экран настроек открыт. Приложение имеет разрешение RECORD_AUDIO. |
| **Post-conditions** | Создан и сохранён локальный звуковой файл (≤5 сек). Файл добавлен в список доступных кряков. Активный кряк может быть заменён на записанный. |

**Основной сценарий:**
1. Пользователь открывает экран настроек.
2. Пользователь переходит в секцию «Выбор кряка».
3. Пользователь нажимает кнопку «Записать свой кряк».
4. Система запрашивает разрешение RECORD_AUDIO (если не выдано ранее).
5. Система открывает экран записи с визуальным таймером и индикатором уровня звука.
6. Пользователь нажимает «Начать запись».
7. Система запускает запись с микрофона.
8. Запись идёт до 5 секунд.
9. Система останавливает запись (по нажатию «Стоп» или по лимиту 5 сек).
10. Система предлагает предпрослушать запись.
11. Пользователь прослушивает запись.
12. Пользователь сохраняет запись.
13. Система сохраняет файл, добавляет в список кряков, помечает как «Свой кряк».
14. Пользователь может установить его как активный кряк.

**Альтернативные сценарии:**
- **9a.** Если лимит 5 сек достигнут: запись останавливается автоматически, система уведомляет «Достигнут лимит 5 секунд».
- **12a.** Пользователь передумал: нажимает «Перезаписать», система начинает новую запись (пункты 6–12 повторяются).
- **12b.** Пользователь нажимает «Отмена»: запись отбрасывается, пустой файл или частичная запись удаляется.

**Обработка ошибок:**
- Если разрешение RECORD_AUDIO не выдано: система показывает экран с объяснением зачем нужен микрофон; без разрешения запись недоступна, но предустановленные кряки работают.
- Если микрофон занят другим приложением: показать сообщение «Микрофон занят. Попробуйте позже» и вернуться на экран настроек.
- Если запись длится 0 секунд (сразу отменена): показать сообщение «Запись слишком короткая (менее 1 сек)» и предложить повторить.
- При нехватке памяти на устройстве: показать сообщение о недостатке свободного места.

## 3. Предложения BA по развитию продукта

Скрытые потребности, не заявленные напрямую в ТЗ, но логично вытекающие из концепции rubber duck debugging:

| ID | Идея | Обоснование ценности |
|---|---|---|
| BA-01 | **«Объясни утке» — текстовый лог сессии.** Поле ввода: разработчик записывает проблему («Как разобрать NullPointer в модуле X»), утка «слушает» (анимация нахождения в размышлении), разработчик формулирует решение вслух. Лог сохраняется локально как «вчерашний дневник кряка». | Фиксирует главную ценность rubber duck: экстернализацию мыслей. Повышает retention — у пользователя появляется накопленный контент. |
| BA-02 | **Таймер «Pomodoro для дебага».** 25 минут работы / 5 минут «отдыха с уткой». | Частая боль разработчиков — пересборка контекста. Таймер с уткой превращает приложение из игрушки в инструмент фокуса. |

## 6. Функциональная область для системного аналитика

### 6.1 Технологический стек (рекомендации)

| Слой | Рекомендация | Обоснование |
|---|---|---|
| UI | **Jetpack Compose + Material 3** | Современный declarative UI, по умолчанию поддерживает темную тему и Material You (динамические цвета); соответствует требованию «современно и красиво» |
| Темы | Светлая + тёмная, следование системной | Material 3 из коробки |
| Анимация | **Lottie** (com.airbnb.lottie) + Spring Animation | Lottie — де-факто стандарт для сложных покадровых анимаций, синхронизация звука через onAnimationEvent |
| Звук | **SoundPool** (для пресетов, короткие звуки) + **MediaPlayer/AudioRecord** (для записи пути) | SoundPool оптимизирован для коротких повторяющихся звуков (кряков) |
| Хранение | **DataStore (Preferences)** + файловая система (записи кряков в filesDir) | Настройки — DataStore; бинарные записи — файлы в собственном хранилище; для темы — фолбэк |
| Виджет | **Glance (Jetpack Glance)** + AppWidgetProvider | Glance — современный Composable-подход к виджетам, поддерживает resizable widget |
| Разрешения | `RECORD_AUDIO` (runtime permission) | Для записи кряка (US-09) |
| min/max SDK | minSdk 26, targetSdk ~34+ | Решение бизнеса (Q3); требования RuStore к targetSdk |

### 6.2 Архитектура (CLEAN / MVVM)

- **Слои:** UI (Compose) → ViewModel → UseCases → Repository → DataSource (DataStore, Files, LocalPreferences).
- **DI:** Hilt.
- **Асинхронность:** Kotlin Coroutines + Flow.
- **Мультиплатформа:** не требуется (Android только).
